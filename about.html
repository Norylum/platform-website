Norylum est un serveur multimédia open source, développé avec l'aide de l'IA, sous direction humaine. MIT License. Code disponible sur GitHub.

Pourquoi ce projet

Norylum est né d'une conviction simple : vos fichiers multimédia n'ont pas à vivre sur le serveur de quelqu'un d'autre. Plex demande un compte. Jellyfin fonctionne mais reste une base de code C# héritée. Il y avait de la place pour quelque chose de propre, rapide, et construit avec les bons outils.

Rust s'est imposé naturellement. L'écosystème async (Tokio, Axum) permet de gérer des centaines de connexions simultanées sans gaspiller de mémoire. SQLite avec WAL est suffisant pour une bibliothèque personnelle et ne nécessite pas d'infrastructure supplémentaire. FFprobe est la référence pour l'inspection des fichiers vidéo.

Ce n'est pas encore un produit fini. Les clients Android, iOS et desktop sont en développement. L'acquisition de contenu (le téléchargement sécurisé via VPN) est en construction. Mais le serveur fonctionne, le protocole est documenté, et le code est là.

Architecture
Monolithe modulaire Rust

Un binaire, plusieurs crates. Chaque domaine (auth, library, streaming, playback, plugins) est un module séparé avec ses propres responsabilités. Pas de microservices, pas d'overhead réseau interne.

AI-Propelled Development

L'IA écrit le code.
Antoine dirige.

"Human-Directed, AI-Built."

Chaque commit est relu et validé par un humain avant d'atterrir dans le repo. L'IA propose, Antoine décide. Les choix d'architecture, les limites de ce qui peut être mergé, les arbitrages entre complexité et robustesse — tout ça reste entre les mains du mainteneur humain.

Ce modèle de développement n'est pas de la magie. L'IA génère du code que les développeurs humains génèrent aussi — avec les mêmes bugs potentiels, les mêmes angles morts. La différence, c'est la vitesse. Et la nécessité d'une relecture encore plus rigoureuse.

Norylum est transparent à ce sujet. Le README du serveur le dit clairement. L'objectif n'est pas de cacher l'implication de l'IA, mais de montrer que ce mode de développement peut produire un code sérieux, testé, avec une architecture cohérente — à condition que quelqu'un de compétent soit aux commandes.

Les tests sont écrits. L'API est documentée. Les décisions d'architecture sont tracées dans les commits. La supervision humaine n'est pas un détail de communication, c'est ce qui différencie un projet AI-Propelled d'un projet AI-generated abandonné.
