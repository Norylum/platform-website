Ce que c'est

Un serveur HTTP qui connaît vos fichiers.

Norylum est un serveur HTTP écrit en Rust. Vous le lancez sur votre machine — un NAS, un vieux PC, un serveur Linux — et il s'occupe du reste : scan de vos dossiers avec FFprobe, indexation des métadonnées dans SQLite, streaming à la demande via HTTP Range requests.

Côté sécurité, il n'y a pas de mode permissif. Toute requête sans token valide est rejetée. Les profils enfants ne peuvent pas accéder à du contenu non classifié. Le code parle d'une politique fail-closed, ce qui signifie qu'en cas de doute, il bloque.

Ce n'est pas encore Plex. Les clients natifs sont en développement. Mais l'API fonctionne, le protocole est documenté, et le serveur est opérationnel.

Pourquoi Norylum
01

Streaming à empreinte mémoire constante.

Le serveur ne charge jamais un fichier vidéo entier en RAM. La lecture s'effectue par morceaux de 64 Ko via des flux asynchrones Tokio. L'empreinte mémoire reste constante quel que soit la taille du fichier — 500 Mo ou 50 Go, même profil d'utilisation.

Direct Play · HTTP 206
O(1) en mémoire

Pas de transcodage, pas de buffer intermédiaire en RAM. La réponse HTTP est un flux ReaderStream + AsyncReadExt::take avec des chunks de 64 Ko. Le client reçoit exactement les bytes demandés dans le header Range.

Supporte 200 OK (flux complet) et 206 Partial Content (plage). Les plages invalides retournent 416 Range Not Satisfiable.

02

Refus par défaut sur toutes les routes.

La politique de sécurité est fail-closed. En cas de doute sur les droits d'accès, le serveur refuse. Il n'y a pas de route accessible sans authentification — à l'exception du /health.

Requête sans token Bearer valide → 401 Unauthorized
Profil enfant + contenu adulte non classifié → 403 Forbidden
Tentative de directory traversal → 403 Forbidden
Token PIN invalide ou expiré → 401 Unauthorized
GET /health → 200 OK (public)

Les erreurs suivent un format JSON uniforme avec un code machine standardisé : UNAUTHORIZED, FORBIDDEN, NOT_FOUND, VALIDATION_ERROR. Pas de messages d'erreur vagues.

10
permissions disponibles
Principe du moindre privilège. Chaque plugin déclare exactement ce dont il a besoin. Rien de plus n'est accordé.
03

Étendre Norylum sans lui faire confiance aveuglément.

Les plugins sont des processus séparés avec un manifeste JSON qui déclare leurs permissions. Un plugin de métadonnées qui veut interroger TMDB doit demander network:outbound explicitement — et l'utilisateur peut décider de l'autoriser ou non.
