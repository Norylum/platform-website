Plugins

Étendre Norylum
sans lui faire confiance.

Chaque plugin déclare les permissions dont il a besoin. Norylum ne lui accorde rien de plus. L'utilisateur contrôle ce qui est autorisé.

Architecture

Un manifeste JSON.
Des permissions déclaratives.

Chaque plugin est défini par un fichier plugin.json qui décrit son identité, sa version, son point d'entrée et les permissions qu'il requiert. Ce manifeste est validé par Norylum avant que le plugin puisse être chargé.

Les permissions suivent le principe du moindre privilège. Un plugin de métadonnées qui veut interroger TMDB doit demander network:outbound explicitement. Un plugin qui ne demande pas library:write ne peut pas modifier votre bibliothèque — même si son code essaie.

L'identifiant d'un plugin (id) est en kebab-case, immuable, et doit être unique dans le catalogue. Une fois publié, il ne change pas. 

{
  "id": "tmdb-metadata",
  "name": "TheMovieDB Metadata Provider",
  "version": "1.0.0",
  "description": "Enrichit les fiches films et\n  séries avec affiches TMDB.",
  "entrypoint": "dist/index.js",
  "type": "metadata",
  "permissions": [
    "library:read",
    "metadata:write",
    "network:outbound"
  ],
  "author": {
    "name": "Norylum Community",
    "url": "https://github.com/norylum"
  },
  "license": "GPL-3.0-or-later",
  "norylum_version": ">=1.0.0"
}
Référentiel des permissions

10 permissions disponibles.

Chaque permission est accordée ou refusée individuellement. L'utilisateur peut installer un plugin en désactivant certaines permissions — le plugin doit en tenir compte.

Permission Description Sensibilité
library:read Lecture des métadonnées de la bibliothèque multimédia Faible
library:write Création ou modification d'éléments dans la bibliothèque Moyenne
metadata:read Consultation des métadonnées enrichies (affiches, synopsis, notes) Faible
metadata:write Écriture de métadonnées, affiches, résumés et notations Moyenne
playback:read Consultation des états et progressions de lecture Faible
playback:write Mise à jour de la progression de visionnage par profil Faible
storage:read Lecture dans le dossier de données propre au plugin Faible
storage:write Écriture dans le dossier de données propre au plugin Faible
network:outbound Requêtes HTTP/HTTPS externes (TMDB, OpenSubtitles, MusicBrainz…) Haute
system:notifications Émission de notifications système aux utilisateurs Moyenne
Catalogue officiel

Les premiers plugins.

Le catalogue officiel est maintenu dans le dépôt norylum/plugins.

tmdb-metadata
TheMovieDB Metadata Provider

Enrichit automatiquement les fiches films et séries avec affiches, synopsis, casting et notations TMDB. Respecte les exigences de logo et d'attribution TMDB dans l'interface.

library:read metadata:write network:outbound
opensubtitles
OpenSubtitles Provider

Télécharge et associe automatiquement les sous-titres depuis OpenSubtitles.org. Supporte SRT et VTT. Indexe les sous-titres par langue et par fichier vidéo.

library:read metadata:write network:outbound
Développement

Créer un plugin.

La spécification complète du manifeste est définie dans le schéma JSON schemas/plugin-manifest.schema.json du dépôt protocol. Un manifeste valide peut être vérifié avec Ajv CLI.

Le point d'entrée peut être un fichier JavaScript, WebAssembly, ou un binaire natif selon la plateforme. La compatibilité de version est déclarée dans le champ norylum_version (SemVer range).

Pour soumettre un plugin au catalogue officiel, ouvrez une pull request sur le dépôt norylum/plugins.

Validation du manifeste
Ajv CLI
npx ajv-cli validate \
  --spec=draft7 \
  -s schemas/plugin-manifest.schema.json \
  -d plugin.json
Champs obligatoires

id           kebab-case · immuable
name         string · lisible
version      SemVer 2.0.0
description  string
entrypoint   chemin relatif
permissions  array (peut être vide)
